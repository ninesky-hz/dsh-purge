# 1.6.48

## 问题

1.6.47 让「应用」在插件版本变化时先干净重解包官方 `app.asar`，但这条判定只接在 CLI 与面板 HTTP 入口上。面板工具 `purge_apply` 直接用 `gatherState()` 给的 `ai_base` 开洗，于是：

- 插件升级后仍在**旧解包树**上增量打补丁；
- 旧版本已经删除的改写继续留在树里（实测 1.1.72 → 1.6.47：`tool-result pruning disabled`、旧 #40 变体、`import "./dsh-purge-hide-console.js"`）；
- 解包戳一直不写版本，下次应用又要靠猜。

## 修法

新增 `core.prepareApplyHost(aiBase)`：以 `forApply: true` 解析宿主，需要时重解包并补写带版本戳。三处入口统一走它：

| 入口 | 位置 |
| --- | --- |
| 面板工具 `purge_apply` | `lib/index.js` 工具执行体 |
| CLI `purge apply` | `lib/index.js` `case "apply"` |
| 重启前预检 | `lib/core.js` `ensureHostClean()` |

面板 HTTP 应用入口本来就带 `forApply: true`，行为不变。

## 验收

- `node --test test/apply-reextract.test.mjs`：4 条，钉住解析顺序与解包戳补写。
- 本机实测（Windows，DSH Desktop 0.2.1-rc.2，插件 1.6.47 → 1.6.48）：工具应用前解包戳只有 `size/mtimeMs`，应用后重解并写入 `version: "1.6.48"`，旧残留改写消失。

不自动应用补丁、不重启 DSH，不改用户提示词与设置。
