# 1.7.21

这一版只做一件事：把 **DSH Desktop 0.2.2-rc.5** 收进已验证宿主清单。82 条补丁的锚点**一条没动**，一条变体都不用加，插件行为没有任何变更。

## 怎么验的

GitHub 的 `dsh-v0.2.2-rc.5` tag 只带源码 archive，没有二进制资产；桌面版二进制在官方更新源：

```
https://download.deepseek.com/dsh-desk/bin/win-x64/deepseek-harness-0.2.2-rc.5-win-x64.exe   # 299,593,552 B
```

流程是「拿官方产物当唯一真相」，不走「本机跑通就算」：

1. 下载 exe（`/S /D=` 静默安装在本机失败，改成直接读安装包）；
2. `7za x dsh-0.2.2-rc.5-win-x64.exe "resources\app.asar"` → `209,083,008 B` 的归档；
3. `lib/extract-asar.js` 的 `extractAsar()` 解包到 `<host>/resources/app`（必须是这个形状，否则 `lib/instance.js` 的 `desktopResourcesForHost()` 匹配不上，`#82/#83/#84` 会假报「不适用」）；
4. `patchDrift()` 逐条核对 → `applyPatches()` 真打两遍 → 对全部目标 `.js` 跑 `node --check`。

## 上游到底改了什么

与 pristine 0.2.2-rc.2（`.work/rc2/host`，0 个 `dsh-purge` 标记）逐字节比对 60 个包内目标文件：**identical 54 / diff 6**。

| 文件 | 变化 |
| --- | --- |
| `dsh-base/cordis.patch.yml`、`dsh-base/package.json` | 配置与版本串 |
| `dsh-repeat-tool-reminder/lib/index.js` | 新增错误码 `CONTENT_REFUSED: {}` |
| `dsh-tool-web/lib/index.js` | `runSearchQueries(ctx, queries, maxResults, llmProvider, signal)` 多一个 `llmProvider`（`exec.agent?.session.requestContext()?.provider`，来自搜索走当前会话模型） |
| `dsh-llm-deepseek/lib/index.js` | 新增 `refusal(details)` → `LlmError(... "CONTENT_REFUSED")`，以及 `delta.stop_reason === "refusal"` 分支 |
| `dsh-client-ui-conversation/lib/client.js` | 前端 bundle |

这 6 处全落在锚点之外。为了把「没漂移」从印象变成证据，又把 rc.5 上命中的每条 pattern 拿去 rc.2 复跑（`rc5-anchor-delta.mjs`，95 行）：**每条在 rc.2 里同样命中，只有 rc.5 才命的条数是 0**。所以 1.7.21 不需要任何新变体——不是「跑起来没报错」，是「锚点文本两版同时成立」。

## 客户端面

- `dsh-client-runtime` / `dsh-client-ui-slots` 仍不在包里（`slots` 的实现内联进前端 bundle 的 seed）；`package.json` 的 `dsh.client.inject` 为兼容老宿主保留旧名，`dsh-client-modules` 的 `arriveGraphRow()` 对不存在的 inject 行直接跳过，不会硬失败。
- 面板用的 `slots` / `locale` / `sessions` / `uiWorkspace` / `conversation` 服务与 4 个 slot 名（`shell.overlay`、`sidebar.panellist`、`main`、`plugins.bundle.config`）在 rc.5 都在；宿主自己的 `dsh-client-ui-plugin-manager` 就是同一套 `ctx.slots.inject` / `ctx.slots.register` 写法。
- 拒绝重试钩子签名没变：`dsh-llm` 仍是 `ctx.waterfall(\`llm/stream\`, options, () => this.adapterStream(options, prepared))`，与 `lib/index.js` 的 `ctx.on("llm/stream", (options, next) => …)` 对得上，§26 那层缓冲/重试不用改。顺带一句：rc.5 自己新增了 `CONTENT_REFUSED` 停止原因，官方层也在处理拒答，插件的 `refusalRetry` 仍然是可选的第二道。

## 白名单与守卫

- `QUALIFIED_HOST_VERSIONS` 增加 `0.2.2-rc.5`（面板/CLI 不再标「未验证」）。
- `test/community.test.mjs` 新增 `0.2.2-rc.5 is a qualified host (1.7.21)`，注释里写清 6 个变更文件与实测数字。
- 另加一条把承诺变成检查的用例：`every qualified host is documented in AGENTS.md and resolves as qualified` —— 白名单里每个版本都必须在 `AGENTS.md` §9 的「已验证宿主」行露面，并且真的被判成 `qualified`。白名单是「逐条锚点在原始宿主源码上验证过」的承诺，没有这条守卫它会慢慢退化成一张没人复核的清单。

## 升级动作

1. 装 1.7.21（插件层）；
2. 在新宿主上点「应用」——rc.5 是全新的原始 `app.asar`，本机从 rc.3 升上来时旧补丁全部失效，`status` 里会看到归档还在或补丁计数归零；
3. **完整退出重开**：补丁写盘不代表当前进程已加载。

面板版本徽标若显示不一致，跑一次 `npm run build:client` 再看（`client.js` 头部的 `// panel-version:` 必须等于 `package.json`）。
