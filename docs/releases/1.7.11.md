# 1.7.11

面板上一屏两个补丁数：hero 写「55/67 条补丁已生效」，顶部条写「磁盘写入计数 64/76」。两个都是"真的"，但分母不同 —— hero 数的是**展示行**，顶部条数的是**补丁 id**。面板把升级链合并显示（`#1–3`、`#5/#11/#12`、`#8–10`、`#45/#46`、`#83/#84`、`#87/#88`），6 个合并组把 15 个 id 压成 6 行，于是 76 条适用补丁只剩 67 行、64 条已应用只剩 55 行。用户在 2026-11-06 的报障截图里看到的就是这个落差，还顺带发现「12 条 skipped」在界面上完全没有出口。

## 数字口径统一到补丁 id

- 新增 `packages/purge-panel/src/shared/patch-count.js`（不 import react，可单测）：`patchIdRowsOf()` 以 `patch_status` 为权威逐 id 展开，`patchRowsOf()` 仍返回合并后的展示行（每行带 `ids`），`patchCounters()` **优先用后端 `patches_*`**，缺失时才自己数，`na` 缺失时按 `patch_status` 里的 `na` 数兜底。
- hero、补丁明细标题、每组表头、顶部条现在同源：`55/67` → **`64/76`**，副标题补上「未生效 12 · 不适用 6 · 共 82 条」，落盘的 12 条 skipped 第一次有了可见出口。
- 合并行保留（升级链仍按 `#1–3` 展示），但计数不再按行数；行首 id 列改用 `idRangeLabel()`。
- `lib/index.js` 的 `/dsh-purge/status`：`patches_pending/skipped/ready/na` 全部改回 id 口径（不再混 `display_*`），另加 `display_patches_applied` / `display_patches_total` 保留分组口径；文本版 status 报表同步。
- `packages/purge-panel/package.json` 的 `test` 脚本补上 `test/patch-count.test.mjs`（以前 `test/*.test.mjs` 只有 version-badge 被显式列出）。

## 同时修掉的真实锚点漂移：#17

- DSH 0.2.2-rc.1 把 `dsh-fs-observation-policy` 的 `editIntent` 重构成一行委托 `return this.requirePresent(target, actor, "edit")`，旧锚点（整段 `FsError` / `FS_NOT_OBSERVED` 函数体）匹配不到；`writeIntent` 又早已带 marker —— 于是 `applied=0, notFound=0`，`rollupPatchStatus` 落到 `skipped`，在面板上表现为"没生效"。
- 新变体只锚那行委托，改成 `return void 0;` + marker 注释；`deleteIntent` 与 `requirePresent(...,"delete")` **保持不动**（有意不放开删除前的读取校验）。
- `test/patch-anchors.test.mjs` 新增两条回归：rc.1 委托形态（write/edit 都 bypass、delete 保留、二次 apply `changed=false`）、旧宿主 inline `editIntent` 仍命中。
