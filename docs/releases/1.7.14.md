# 1.7.14 — 本机备份可以单份删除

本机备份以前只有两个出口：建一份、回滚到一份。想清掉中间某一份，只能 `prune` 整片清空，或者去 `$DSH_HOME/dsh-purge-community/backups/` 底下手工删目录 —— 后者绕过了锁，也绕过了去重对象的回收。这个版本补上「删除单份」：存储层一个方法，往上串成 HTTP op、CLI 子命令和面板按钮，四条入口指向同一段逻辑。

## 语义

删除的是 `<DSH_HOME>/dsh-purge-community/backups/<id>` 这一份快照目录，删完顺手回收已经没人引用的去重对象。

它**不是**「撤销」：已安装的插件、当前的提示词、规则集、profile 配置一概不动，释放的只有磁盘。被删掉的那一份不可再回滚，其余快照照旧能用。

## 一处实现，四处入口

| 层 | 入口 | 说明 |
| --- | --- | --- |
| 存储 | `Maintenance.remove(id)` | 锁 → 校验 → 统计 → 删除 → GC，返回 `{ok, removed_id, freed, gc, remaining, usage}` |
| HTTP | `POST /dsh-purge/community` `{"op":"delete","id":"<备份ID>"}` | 与 `backup` / `rollback` / `prune` 同一分派表，错误仍旧 400 + `{ok:false,error}` |
| CLI | `purge-community delete <备份ID>` | 输出同上 JSON，成功退出 0，失败非 0 |
| 面板 | 「本机备份」操作行的 `删除备份` | 需先选中；点击前弹确认 |

## 不变量

1. **只删那一份目录**。路径由 `validId(id)` 校验后拼成 `path.join(this.backups, target)`，不接受 `..`、绝对路径、任意名字。
2. **同一把锁**。`remove()` 走 `locked()`，与 `backup()` / `rollback()` 共用 `maintenance.lock`；已有维护在进行时拒绝，不并发改备份树。
3. **拒绝符号链接**。先 `lstat`：不存在 → `备份不存在：<id>`；不是目录或是链接 → `备份路径无效，未删除`。再 `realpathSync(folder)` 与目录本身比对，不等 → `备份路径不能为符号链接`，与 `verify()` 同一口径。
4. **不跟穿 junction**。删除走 `removeTreeNoFollowSync()`，不是 `fs.rmSync(folder, { recursive: true })`：后者在 Windows Electron 上会跟进 junction 把目标目录一起清掉（1.6.46 / #67 的事故）。
5. **删完就 GC**。`gcObjects()` 回收不再被任何快照引用的对象，`freed` 是删除前 `treeBytes()` 统计的字节数。
6. **不动别的**。已安装插件、当前提示词、规则、profile 配置、其他快照都不受影响。

## 面板

- 「本机备份」标题右侧多一条占用读数：`共 N 份 · 占用 X`（字节按 KB/MB 保留一位小数，0 份时只写「共 0 份」）。加载中或失败时不显示 —— 宁可空着，也不显示上一次的旧数字。
- 操作行在 `回滚插件` 之后多一个 `删除备份`，`disabled` 条件是 `busy || !selected || listState !== "ready"`：没选中不能删，列表没就绪也不能删。
- 确认文案：`只删除本机这一份快照（含其去重对象），不影响已安装插件、当前提示词与规则；删除后无法再回滚到它。继续？` —— 与 `rollback` / `update` 的确认写法一致，取消时一个请求都不发。
- 完成后提示 `已删除备份 <id>，释放 <大小>`，列表由既有的 `load()` 刷新，选中项由既有的 `setSelected` 逻辑清空 —— 没有为删除另写一套刷新或清空。

## 残留清理

没有 `manifest.json` 的未完成快照不进 `list()`：面板上看不见，`rollback` 也不会认它，`prune` 只按 `list()` 的结果算。这类目录以前只能手工删。现在只要目录名能过 `validId()`，`delete <id>` 就能清掉它 —— 这是残留快照的唯一出路，也是本版特意保留的行为（不要求目录里有 manifest）。
