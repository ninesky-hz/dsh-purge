# 1.7.3

换包终态识别、测试隔离与 Windows 换行守卫。没有行为变更：补丁表、权限、提示词、更新策略都不动。

## 起因

上一版之后留在工作区四处未提交的修复，都不是新功能，而是"本机能过、换台机器或换个时序就红"的坑：

1. 宿主完成 asar 换包后，`app.asar` 已经不在了（被助手改名成 `app.asar.purge-<token>.bak`），旧的判据只看归档是否存在，于是把这个**成功的终态**读成「归档缺失」；
2. `instance.js` 与 `desktop.js` 各存一份"宿主主包"清单，其中一份改了另一份不会跟着改；
3. `npm test` 里关于"默认发行源是 GitHub"的断言，在设了 `PURGE_UPDATE_REPO=n-sky/dsh-purge` + `PURGE_UPDATE_PROVIDER=gitee` 的机器上整片变红（本机实测 13 条），失败原因与被测代码毫无关系；
4. `client.js` 是生成的 UI 产物，`check:client` 按字节比较 LF；Windows 上 `core.autocrlf=true` 的检出会把它变成 CRLF，测试必然误报"产物过期"。

## 改动

| 文件 | 内容 |
| --- | --- |
| `lib/desktop.js` | 新增 `unpackedFinalLayout(exe)`：三条磁盘证据（`app.asar` 不是文件、`resources/app` 是目录、其下能找到三个 DSH 主包之一的 `package.json`）同时成立才判定为换包终态；任一不成立返回带 `reason` 的否定结果，交回原有分支。另开 `spawnHelper` 注入缝（仅测试用，不传时与生产默认完全一致） |
| `lib/instance.js` | `HOST_PACKAGES` 与 `componentRoots()` 收成一份，`normalizeHostBase` 与调用方共用；不再有第二份名单 |
| `test/diagnostic-host.test.mjs` | 归档在 / 归档已换包 / `app` 缺失 / 主包缺失四种形态 |
| `test/unpacked-restart-guard.test.mjs` | 换包等待期与完成后的重启守卫 |
| `test/env-isolate.mjs` | 清掉继承的 `PURGE_UPDATE_REPO` / `PURGE_UPDATE_PROVIDER` / `PURGE_GH_MIRROR` |
| `package.json` | `test` 脚本加 `--import ./test/env-isolate.mjs` |
| `.gitattributes` | `client.js -text`，生成物不做换行转换 |
| `.gitignore` | 忽略 dsh-main-agent 的循环记账（`.agi/loop-state*.json`、`.agi/BRIEF.md`） |

### 为什么证据要"同一个 `<resources>`"

`unpackedFinalLayout()` 只读 `exe → resources → app` 这一条物理路径，不扫 PATH、不看兄弟安装、不查全局。换包助手在别的目录里留下 `app.asar` 残留时，不会被这份判断当成"当前实例还密封着"。

### 为什么测试隔离要进 `npm test`

`node --test` 会把 `--import` 传给子进程，所以隔离对每个测试文件生效，而不是只对入口生效。此前把这些变量设为机器级（`HKCU\Environment`）的用户，会因为一个与代码无关的环境差异得到一片红。

## 升级须知

- 装完仍需手动「应用」+ 完整退出重开，补丁才会加载；本版没有新增补丁，也没有改锚点。
- 若你的 Gitee 镜像要作为面板更新源，需要该仓库有带 `dsh-purge-community-<version>.tgz` 与 `SHA256SUMS.txt` 的 Release；只有 tag 时降级路径会因缺校验清单拒绝安装（这是故意的）。
- `PURGE_UPDATE_REPO` / `PURGE_UPDATE_PROVIDER` 属于**机器级**配置，不随仓库走；换机器要重设。
