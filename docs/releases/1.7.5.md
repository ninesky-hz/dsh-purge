# 1.7.5

第一条写进宿主本体（`dsh-desktop-host`）的补丁：把「启动途中被 shutdown」从崩溃框改成静默退出。

## 现象

点「应用」→ 手动重启 DSH → 弹出：

```
DeepSeek Harness is unavailable
The application could not start or stopped unexpectedly.
cannot create effect on inactive context
```

再点一次就正常进。`selfcheck` 全程 69/69 全绿，补丁没有写坏。

## 根因

宿主自己的 `main()`：

```js
const { ctx } = await application;                                  // boot 完成
control.updateTasks = installDesktopUpdateTaskControl(ctx);          // ← 这里抛
control.quitInspection = installDesktopQuitInspection(ctx);
```

`installDesktopUpdateTaskControl` 第一件事就是 `ctx.effect(...)`。如果 boot 期间收到过 `shutdown`（用户/系统正在退出，或启动与退出撞在一起），这个 `ctx` 已被 dispose，`ctx.effect` 抛：

```
CordisError: cannot create effect on inactive context   code: INACTIVE_EFFECT
    at Fiber.effect (cordis/lib/index.js:1171)
    at installDesktopUpdateTaskControl (dsh-desktop-host/lib/index.js:112)
    at main (dsh-desktop-host/lib/index.js:329)
```

宿主把异常通过 IPC 报成 `fatal`，Electron 侧 `DesktopFatalRecovery` 就弹出那个「无法启动」对话框。

**本次实测证据**：用同样的 argv 直接启动宿主（隔离 `DSH_HOME`，一次全新、一次复制真实 home）两次都正常起来，只出现与退出无关的 telemetry 配置警告和一次 `Fiber._reload`；也就是说宿主单独 boot 没问题，只有「boot 期间被要求退出」才会走到这个异常。

## 改法（#91 `DESKTOP_HOST_BOOT_INACTIVE_QUIET`）

```js
const { ctx } = await application;
// [dsh-purge] boot 途中收到 shutdown 时 ctx 已 dispose：静默退出，不抛 fatal 对话框
try {
	control.updateTasks = installDesktopUpdateTaskControl(ctx);
	control.quitInspection = installDesktopQuitInspection(ctx);
} catch (error) {
	if (stopping !== void 0 && error && error.code === "INACTIVE_EFFECT") {
		await send({ type: "shutdown-complete" });
		if (process.connected) process.disconnect();
		process.exit(0);
	}
	throw error;
}
```

- 只在 `stopping !== void 0`（确实在走退出流程）且错误码精确等于 `INACTIVE_EFFECT` 时接管；
- 接管后先回 `shutdown-complete`（shell 的 `stop()` 在等它），断开 IPC，`exit(0)`；
- shell 侧已有的 #83 把 `code=0` 视为正常退出，不再弹崩溃框；
- **其他任何错误照旧 `throw`**，不把真故障静默掉。

改动落在 `dsh-desktop-host/lib/index.js`，这是本插件第一次新增宿主本体目标键 `desktop-host`：

- `targetFiles()` 新增 `desktop-host`（覆盖平铺与 `dsh/node_modules` 两种布局）；
- 补丁标 `optional: true` + `surfaces: ["desktop"]`，宿主不在场时显示「不适用」而不是失败；
- `selfcheck` 的「桌面宿主启动兜底」层从 `[82, 83, 84]` 扩到 `[82, 83, 84, 91]`。
