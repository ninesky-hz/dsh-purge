# 1.7.12

宿主 0.2.2-rc.1 把 `list_agents` 并进了 `dsh-tool-subagent-control` 本体（包的 exports 里不再有 `./list-agents`），`dsh-workflow-worker-thread` 也不再随宿主发布。旧预设还留着那两行，于是 `设置 → Agent 预设` 里「红队模式」挂着「加载失败」，「无限制模式」直接不在列表里——一条死行把整份预设判死。

- **两条预设表现不同的原因**：`redteam` 由 `lib/redteam/index.js` 注册一次，broken 记录留在 registry，界面显示徽标；`unrestricted` 走 `registerPresetDefinitions()`，`resolve().broken` 直接抛错 → 释放 + 重试 40 次 → 从未注册 → 列表里没有它。证据在 `$DSH_HOME/redteam/preset-declare.json`：`broken: "tool-subagent-list-agents (@deepseek-ai/dsh-tool-subagent-control/list-agents): never started"`。
- **数据层**：`presets/redteam|unrestricted/agent.cordis.yml` 与 `$DSH_HOME/.agent-presets/redteam|unrestricted/agent.cordis.yml` 删掉 `tool-subagent-list-agents` 与 `workflow-worker-thread` 两行（删前留 `.bak-<ts>`）。`unrestricted` 带 `# managed-by: dsh-purge`，下次安装会同步；`redteam` 是用户自有文件，就地改。
- **代码层**：`lib/preset-compat.js` 新增 `dropPresetRow(rows, name)` 与 `registerPresetDefinitions(registry, definitions, { onPruned, maxRowDrops = 12 })`。注册失败且消息匹配 `/(\S+) \((.+?)\): never started/` 时只删该模块名的行（含 `group: true` 的 `config` 内）再重试；匹配不到或删不到任何行照旧抛出——不把真的加载错误当无害。`presets-plugin.js` 与 `lib/redteam/index.js` 都接了回调：warn 日志 + `preset-declare.json` 的 `pruned` 数组。
- **回归**：`test/preset-compat.test.mjs` 加三条（剪枝重试且不修改调用方定义、无关 broken 仍抛出、模板不再声明这两个模块且 `list_agents` 仍由 control 包提供），7/7 通过。
- **升级**：插件运行时代码与预设文件都变了，要覆盖 profile 的 `node_modules/dsh-purge-community` 并完整退出重开；只刷新面板不够。

## 发行源改为我们自己的 Gitee 仓

上一版起面板「维护 → 检查社区版更新」报 `无法读取社区发行列表：GitHub 资源不存在或无访问权限（HTTP 404）；标签 降级失败：… HTTP 404`。代码里的默认源仍指向上游 GitHub 仓，而我们的发行包已经搬到 Gitee，于是列表、标签兜底、发行记录链接全部指向一个取不到的地址。

- **默认源**：`lib/update-source.js` 的 `DEFAULT_REPOSITORY` 改为 `n-sky/dsh-purge`，`DEFAULT_PROVIDER` 改为 `gitee`。`PURGE_UPDATE_REPO` / `PURGE_UPDATE_PROVIDER` 仍是覆盖手段，显式写 `PURGE_UPDATE_PROVIDER=github` 就还是老行为。`lib/update-net.js` 的 `SOURCE_REPO` 不再第二处硬编码，从 `DEFAULT_REPOSITORY` 派生；`UPSTREAM_REPO` 这个名字为外部脚本保留，值同源。
- **面板与包元数据**：维护页「发行记录」指向 `https://gitee.com/n-sky/dsh-purge/releases`，欢迎语里的仓库链接、`package.json` 的 `repository` / `homepage` / `bugs` / `dsh.install.*`、面板包的 `repository` 一并换到 `n-sky/dsh-purge`。NOTICE、CONTRIBUTORS 和历史发行说明里的上游链接是归属记录，保持原样。
- **错误文案按 provider 显示**：`httpFailure()` 不再写死「GitHub 资源不存在…」，改为按活动源的 label 生成（`Gitee 资源不存在或无访问权限（HTTP 404）`），额度与认证提示里的 token 名也跟着走（`GITEE_TOKEN` / `GITHUB_TOKEN`）。代理 CONNECT 失败单独标「更新代理」，不冒充发行源。
- **完整性校验边界**：源码 ZIP 通道的逐文件校验现在按活动源取 Git tree。Gitee v5 的 `commits/:ref` → `git/trees/:sha?recursive=1` 与 GitHub 同形，blob 摘要都是 Git 的 `sha1("blob <len>\0"+bytes)`，所以两个源走同一套校验（只有 API 基址与树节点 mode 拼写不同：GitHub `040000`，Gitee `40000`）。provider 没有 tree 接口时**不**静默跳过，直接 fail-closed 报「不支持 Git tree 逐文件校验；请改走发行包（.tgz + SHA256SUMS）通道」。面板安装发行包（`dsh-purge-community-x.y.z.tgz` + `SHA256SUMS.txt`）不走这条 ZIP 校验，改源不会挡住它。
- **安装入口**：`scripts/install.sh` / `install.ps1` 的 bootstrap 下载基址改为 `https://gitee.com/n-sky/dsh-purge/raw/master/...`；`scripts/bootstrap-install.mjs` 用 Gitee `releases/latest` 与 `releases/download/vX.Y.Z/` 取包与摘要，包身份校验接受新旧两种 `repository.url`（历史上已发布的版本写的是 GitHub 仓），SHA256 校验不变。
- **校验**：`node --test test/update-source.test.mjs test/update-source-provider.test.mjs test/update-http.test.mjs test/update-integrity.test.mjs`、`node --test test/bootstrap-install.test.mjs test/bootstrap-download.test.mjs`、`npm run check:docs`、`npm run check:client` 全绿。


## 测试脚手架事故与修复（2026-11-06）

`test/desktop-presets.mjs` 在临时 profile 里建了一个指向宿主 `node_modules/@deepseek-ai` 的 junction，回收时用 `fs.rmSync(home, { recursive: true, force: true })`。在 Electron 44.7.0 的 **Node 24.21.0** 上，这个原生递归删除会跟着 junction 进入目标目录，把真实安装的 331 个包、10721 个文件清空（同日本机实测：Node 22.20.0 不跟；改回 `removeTreeNoFollowSync()` 后目标目录文件数不变）。运行中的宿主靠内存继续工作，但下次启动会缺依赖——必须从 `app.asar.purge-<token>.bak` 选择性解包恢复。

- **修法**：`test/desktop-presets.mjs` 的 `finally` 改用 `lib/remove-tree.js` 的 `removeTreeNoFollowSync(home)`（`lstat` → 符号链接只 `unlink`，绝不递归进目标）。这正是 #67 为 Windows junction 准备的同一个函数。
- **回归**：`test/remove-tree.test.mjs` 新增一条静态断言——该文件不得再出现 `rmSync(..., { recursive: true })`，且必须调用 `removeTreeNoFollowSync(home)`。
- **教训**：任何"临时目录里塞 junction / symlink 再整目录删"的写法在 Windows + Node 24 上都会伤到目标；删除前先 `unlink` 链接，或直接用 `removeTreeNoFollow*`。
