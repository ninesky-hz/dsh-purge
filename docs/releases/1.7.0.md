# 1.7.0 — 随包知识库：101 个渗透技能装完即用

## 问题

1.6.x 的技能体系只有两处：包内 `skills/redteam/*.md`（23 个单文件红队技能，要查本机工具路径）和官方
`$DSH_HOME/skills`（用户自己的技能）。想要一份成体系的渗透知识，只能自己找仓库、自己 `/skills import`，
而且导入后落在官方目录，与用户技能挤在一起，删插件也删不干净。

知识库本身是**目录束**形态（`<id>/SKILL.md` + 同目录深读文档），与现有单文件技能不是同一种结构；
`$DSH_HOME/skills` 又是本包"只读不写"的官方目录。所以不能直接整目录倒进去，需要一条自己的落地链路。

同步是**内容比对**：`$DSH_HOME/redteam/hackskills` 已与包内一致时 `written = 0`；`$DSH_HOME` 与 `~/.dsh`
分叉的老机器两边各同步一份。只同步 `.md`，`LICENSE` / `SOURCE.json` 留在包里，不塞进技能目录
（否则会被当成非技能文件混在 101 个目录里）。

## 行为变化

- 装完/更新后，红队预设作用域里多出 101 个技能；`<available_skills>` 目录摘要约 28 KB（≈8 k tokens/会话），
  正文只在模型真正加载某个技能时读取。
- 技能页出现第三个分组，标题「知识库技能」；它们一律显示「已列出」，不做本机工具检测（文档型，没有外部依赖）。
- 老用户预设不会被覆盖：只补 `dshHomePath('redteam/hackskills')` 一行，其余内容（含用户自己加的注释、
  改过的模型与工具配置）原样保留。要整份覆盖仍用 `REDTEAM_PRESET_REFRESH=1`。
- 知识库不写 `$DSH_HOME/skills`：官方目录依旧只读。

## 已知缺口

- 上游总路由与注入分类路由里有两条指向 `../nosql-injection/SKILL.md` 的死链，上游从未提供该目录：
  已删掉这两行。需要 NoSQL 注入思路时按 SQLi 与注入分类推导，别指望能加载到正文。
- `ssti-server-side-template-injection` 与 `upload-insecure-files` 提到的 `SCENARIOS.md` 上游没有打包：
  6 处引用降级成纯文本（`SCENARIOS.md（上游未随包提供）`），避免模型去读一个不存在的文件。
- 内容为上游原样，未做质量重写；升级上游时按 `docs/HACKSKILLS.md` §9 的步骤覆盖并重跑测试。
- 目录摘要常驻会话上下文是这份知识库的固有成本：接受不了就按 §8 的方式在预设层关掉。
