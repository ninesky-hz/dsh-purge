# 1.7.17 — 对齐 DSH Desktop 0.2.2-rc.2

上游这一版没动工具面，动的是**拦人那条链路的形状**：沙箱升级的拒绝从 `throw new Error(...)` 换成 `SandboxEscalationError` + 错误码，工具审批询问整体从 `dsh-tools/lib/index.js` 搬进 `dsh-tools/lib/pipeline.js` 的 `serviceAsk()`，Inspector 学会了自己扣状态帧的 record 包装预留。于是 #13 / #35 / #62 / #92 四条补丁的锚点全部落空。

不复核就点「应用」的后果不是报错，是**静默 skipped**：面板显示「不适用」，破甲链路少了审批与沙箱两段，而模型看起来照常工作。

基线是 npm 上的 `@deepseek-ai/*@0.2.2-rc.2`（45 个包自证 `version=0.2.2-rc.2`；`@deepseek-ai/dsh-desktop-host` 不在 npm 发布，桌面本体 #91 本轮只能标 unverified）。

## 改了什么

### #13 / #35：沙箱升级换了错误类（必需）

`dsh-sandbox/lib/index.js` 现在是这样：

```js
if (!(WIDER_MODES[effectiveMode] ?? []).includes(mode))
  throw new SandboxEscalationError(`sandbox escalation to "${mode}" is not strictly wider than this call's current "${effectiveMode}" mode`, "SANDBOX_ESCALATION_INVALID_ARGUMENT");
if (approval.approver === void 0)
  throw new SandboxEscalationError(`...`, "SANDBOX_ESCALATION_UNAVAILABLE");
```

拒绝分支还多插了一行才 throw：

```js
case "cancelled":
  approval.signal?.throwIfAborted();
  throw new SandboxEscalationError(`...`, "SANDBOX_ESCALATION_CANCELLED");
```

两条补丁按 rc.2 真实字节重写锚点。语义没变：**不拦、不问、不拒**。

### #62：审批询问搬进 pipeline（可选）

`serviceAsk()` 现在统一走 `approvalDenial(reason, CODE)`，deny 的构造从内联对象换成了 helper，`dsh-tools/lib/index.js` 与 `lib/types/index.js` 里 `requires approval` 已经 0 命中。补 6 条变体：`lib/pipeline.js`（tab 风格）+ `lib/types/pipeline.js`（4 空格、`undefined` 而非 `void 0`），各三条 —— 无审批服务、无 Agent 可路由、通道打不开。

**边界没动**：只放行「没有通道」；`rejected` 与 `cancelled` 仍然 deny。用户点了拒绝就是拒绝，这一条不因为「更顺手」而放宽。

### #92：Inspector 自己扣预留了（可选）

rc.2 把 `maxSourceFrameBytes - 4096` 改成了 `maxStatePayloadBytes(spec.maxSourceFrameBytes)`，并新增 `STATE_RECORD_OVERHEAD_BYTES = 1024` 与 `maxStatePayloadBytes()` —— 上游自己把 record 包装的账算清了。

旧补丁的 `- 8192` 是给 1.7.6 那个「record 比 payload 多约 50 B」的窗口留的余量。搬到 rc.2 上照抄，就是**重复扣一次**，快照预算白掉 4 KiB。所以新变体只加注释、不再改算术；`DEFAULT_MAX_SOURCE_FRAME_BYTES` 抬到 1 MiB 的那条保留（这一条与 record 预算无关，仍是把裁剪上限抬上去）。

### #56 / #77：回退隐藏被上游移走（可选）

`hidden.add` / `isRewindMarker` / `rewindVisibleEntries` / `rewind` 在 `dsh-client-ui-conversation/lib/client.js` 以及它的 89 个 source 里全部 0 命中 —— 回退的可见性逻辑已经不在这个包里了。两条加 `settleWhenAbsent: true`，不再误报 optionalDrift。

#77 的情况更细：`append` 只剩压缩写法，且依赖的 `isRewindMarker` 不存在。补上去会写出引用未定义函数的代码，所以**这一版不补**，等上游把逻辑放回来再跟着锚。

### #30 / #65：每点一次应用都 changed

`#65` 的产物会写回 `merged.decision === "deny"` 形态，而 `#30` 的 pattern 正是这一行 —— 于是 `#30` 每次都能再命中一次，`applied` 计数每次都有它，永远到不了幂等。现在 `#65` 改写为 `"__dsh_purge_deny_disabled__"` 哨兵 + `else if`，pass1 == pass2。

### `patchDrift().partialDrift`

#92 这类「一条锚点命中、另一条失效」的补丁以前既不报 drifted 也不报 ok：判定条件是 `!hitAny && anchors.length`，部分命中被吞。现在单独进 `partialDrift`（`reason: "partial_anchor_drift"`），复核时看得见。`drifted` / `optionalDrift` 的语义不变。

### 预设：两个键名在 rc.2 变了

| 键 | rc.2 实际 | 处理 |
| --- | --- | --- |
| `modelSelectionSettings: true` | 改名 `modelSelection` | 双写：老宿主认前者，rc.2 认后者 |
| `backgroundMode: continuable` | 整个移除（rc.3 / rc.5 也 0 命中） | 删除所有出现 |

双写不脏：schemastery 的 object resolver 末行是 `if (!strict) merge(result, data)`，未知键原样保留、不报错。所以两个宿主都能吃到自己认的那个。

顺带确认一件容易被误判的事：`migratePresetDefinition()` 在注册前就把 `toolFilter` 转成了子预设 + `agentPreset` 引用，所以 rc.2 那句 `toolFilter is no longer supported` 抛不到，预设不会整份 broken。

## 升级

1. 装 1.7.17；
2. 点「应用」（它会把 rc.2 的四条新变体写进去）；
3. **从系统托盘完整退出** DSH，再打开。

第 3 步不能省：补丁写盘不代表当前进程加载。rc.2 桌面宿主如果还在密封状态（`app.asar` 存在），「应用」会走换包流程，`handoff.phase` 到 `complete` 才算换完。

`@deepseek-ai/dsh-desktop-host` 不在 npm 发布，桌面本体的 #82 / #83 / #84 / #91 在本轮基线里没法验证，真机上请另跑一次 `purge-community diagnose` 看这四条。
