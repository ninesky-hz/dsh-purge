# 1.7.10

面板不再自带版本号：徽标以前渲染的是构建期常量 `__PANEL_VERSION__`，1.7.9 发版漏跑 `npm run build:client`，`client.js` 里烙着的还是 1.7.8 —— 于是装的是 1.7.9、面板显示 1.7.8，顶部还常驻一条「官方版本 1.7.9；界面 1.7.8。两者不一致…」的黄条。那条黄条本身也拿后端版本和同一个常量比，所以必然不相等。

## 现在怎么拿版本

两个值都来自运行时，界面不参与"猜"：

| 字段 | 来源 | 含义 |
| --- | --- | --- |
| `plugin_version` | `updater.runningVersion()`（模块加载时读 `package.json`） | 真正装着的插件版本 |
| `panel_version` | `updater.panelBundleVersion()` 读包内 `client.js` 头部 4 KB 的 `// panel-version:` 标记 | 当前被服务的界面代码是哪一版构建的 |

- 徽标与状态条「插件」都渲染 `plugin_version`；后端尚未响应时只显示「社区版」，不回退到任何写死的版本号。
- 黄条只在 `panel_version !== plugin_version` 时出现，文案为「插件已装 X，界面代码却是 Y 构建的。界面可能缺新设置项，请重启 DSH 重新加载界面。」
- 独立面板（非社区版）保留原语义：以验证过的上游接口版本 `1.1.71` 为基线，那是兼容契约，不是面板自身版本。

## 改了哪些文件

- `packages/purge-panel/scripts/build.mjs`：产物头部写 `// panel-version: <pkg.version>`（后端据此识别界面构建版本）。
- `lib/update.js`：新增 `panelBundleVersion()`，只读 4 KB，读不到返回空串。
- `lib/index.js`：`/dsh-purge/status` 与 `/dsh-purge/community` 带出 `panel_version`。
- `packages/purge-panel/src/shared/versions.js`：`installedVersion` / `bundleVersion` / `versionBadge` / `bundleDrift`。
- `packages/purge-panel/src/components/page.js`、`settings-shell.js`：徽标与提示改用上述 helper，移除 `__PANEL_VERSION__` 的所有渲染用途。

## 校验

```sh
npm run build:client && npm run check:client
npm --prefix packages/purge-panel run build && npm --prefix packages/purge-panel test
npm run test:ui
npm run check:docs
```

`packages/purge-panel/test/version-badge.test.mjs` 断言：徽标跟随后端版本、缺信息时不编造版本、drift 只在真不一致时触发、`client.js` 头部 marker 等于 `package.json` 版本、bundle 内不再出现「社区版 1.x.y」这类常量。

## 附带修复

`packages/purge-panel/test/maintenance.test.cjs` 里按钮与空态文案还停在重构前（「刷新备份列表」/「暂无备份」），与 `maintenance.js` 的「刷新」/「还没有本机备份」对不上，导致该单测长期失败；本版同步标签，恢复 23/23。

## 升级

面板代码是插件运行时模块：安装后仍需手动「应用」并完整退出重开 DSH，仅仅刷新浏览器不会加载新版界面。
