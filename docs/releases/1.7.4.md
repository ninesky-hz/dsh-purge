# 1.7.4

修一个会把启动拦住的崩溃框：桌面已解包后点「应用」，不再自动重启。

## 现象

点「应用」→ 手动重启 DSH → 弹出：

```
DeepSeek Harness is unavailable
The application could not start or stopped unexpectedly.
cannot create effect on inactive context
```

## 根因（不是补丁被写坏）

崩溃栈落在 DSH 自己的桌面宿主，不在本插件的补丁目标里：

```
CordisError: cannot create effect on inactive context
    at Fiber.effect (.../@deepseek-ai/cordis/lib/index.js:1171)
    at installDesktopUpdateTaskControl (.../@deepseek-ai/dsh-desktop-host/lib/index.js:112)
    at main (.../@deepseek-ai/dsh-desktop-host/lib/index.js:329)
  code: 'INACTIVE_EFFECT'
```

`main()` 里 `const { ctx } = await application;` 之后紧接着装更新任务控制；如果宿主在 boot 途中收到 `shutdown`，这个 `ctx` 已被 dispose，`ctx.effect(...)` 就抛 `INACTIVE_EFFECT`，宿主发 `fatal`，Electron 弹出上面那个框。

而触发 shutdown 的，正是**两次重启撞在一起**：1.7.3 及更早在已解包桌面点「应用」会请求一次重启（`hostctl.scheduleRestart`），如果用户这时又从托盘退一次，新宿主刚起来就被要求退出。

本机实测的指纹：7 次崩溃全部在 apply 之后 13–21 秒内，且下一次直接打开就正常；崩溃日志里的 shell pid 都已经不在运行。

## 改法

| 位置 | 改动 |
| --- | --- |
| `lib/settle-policy.js` | `applyShouldRestart()` 增加 `surface` 参数：`sealed` 仍返回 `true`（换包必须完全退出）；`surface === "desktop"` 且未密封时返回 `false` |
| `lib/index.js` | 应用处理器取 `currentSettleScope()`，把 surface 与 sealed 一起传进去；新增 `deferredDesktopRestart` 提示分支：「补丁已写入磁盘，请从系统托盘完全退出后重新打开一次」 |

不变的部分：

- **密封桌面**仍走换包握手（`waiting_for_quit` → 用户完整退出 → `complete`）；
- **Web / headless / 未知 surface** 仍是写盘后重启，行为与 1.7.3 一致；
- 补丁表、权限预设、提示词注入、更新策略一个字没动。

## 回归

新增 `test/apply-restart-policy.test.mjs`（4 条）：

1. 密封桌面 → 仍重启；
2. 解包桌面（complete / appliedCount / promptReady 三种输入）→ 不重启；
3. web 与未知 surface → 保持旧规则；
4. `INACTIVE_EFFECT` 与 `inactive context` 文案都能被 `isInactiveContextError()` 识别。

```
npm test          → 见 release commit 的实测数字
npm run check:docs
npm run check:client
```

## 升级须知

- 装完仍要手动「应用」；**桌面已解包时不会再自动重启**，请按提示从托盘完全退出，再手动打开一次。
- 若已经弹过那个框：点 `Exit`，等两秒，从图标正常打开一次即可，不需要重装。
- 崩溃日志位置：`%APPDATA%\@deepseek-ai\dsh-desktop\logs\crash-*-host.log`。
