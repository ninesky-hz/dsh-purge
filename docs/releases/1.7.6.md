# 1.7.6

修一个会把整个宿主带走的 bug：插件树变大以后，实验性 Inspector 的状态帧预算差几十字节，发一条消息就可能让 DSH 退出。

## 现象

DSH 能正常启动、正常进会话，但在任意对话框里**发一条消息**就弹：

```
DeepSeek Harness is unavailable
The application could not start or stopped unexpectedly.
dsh: fatal uncaught exception: Error: inspector: source state exceeds the source-frame byte limit
```

崩溃日志 `%APPDATA%\@deepseek-ai\dsh-desktop\logs\crash-*-host.log` 里的栈只有一条：

```
InspectorSourceBuffer.setState        dsh-experimental-inspector/lib/index.js:996
HostBridgePublisher.setState          .../index.js:1109
HostInspectorSource.setState          .../index.js:836
index.js:2322                         publishCordisTree
index.js:2294                         publish
```

`selfcheck` 可能是全绿的：补丁没写坏，权限也没问题。

## 根因

`publishCordisTree` 是宿主里唯一把 Cordis 插件树按 state 发布的调用点，两处预算各说各话：

| 环节 | 约束 |
| --- | --- |
| 采集器裁剪快照 | `maxSourceFrameBytes - 4096` = 126 976 B |
| `InspectorSourceBuffer.stateFits()` | `json({monotonicMs,topic,payload}) + 4096 <= maxSourceFrameBytes`（131 072 B） |
| state record 比 payload 多 | 约 50 B 的包装 |

于是快照只要被裁到「离上限 50 字节以内」，`setState` 必然抛错。这个异常发生在 Cordis 状态通知的微任务里，没人接 → `dsh: fatal uncaught exception` → 宿主 exit 1 → shell 弹框。

- **为什么「重启能正常进」**：启动那一刻快照刚好躲过那个窗口；
- **为什么「发消息才崩」**：新建会话级 fiber 会触发一次新的树发布，撞窗口就死，所以是随机的；
- **为什么最近才出现**：插件树随会话/bundle 增长（purge、main-agent、disk-guard、reverse-skill 等都在往里加 fiber），迟早压到裁剪上限。

数值（`test/patch-anchors.test.mjs` 里有同样的断言）：

```
快照 126 976 B → record 127 041 B → +4096 = 131 137 B > 131 072 B → 抛
快照 126 936 B → record 127 001 B → +4096 = 131 097 B > 131 072 B → 抛（差 40 字节也崩）
预算 122 880 B → record 122 945 B → +4096 = 127 041 B           → 通过
```

## 改法（#92 `INSPECTOR_STATE_FRAME_HEADROOM`）

只改 `dsh-experimental-inspector/lib/index.js` 两处：

- 快照预算 `maxSourceFrameBytes - 4096` → `- 8192`（给 record 包装留 4 KB 余量）；
- 默认帧预算 `DEFAULT_MAX_SOURCE_FRAME_BYTES = 128 * 1024` → `1024 * 1024`（2 048 节点上限的树不再被裁）。

新增宿主目标键 `inspector`（平铺 + `dsh/node_modules` 两种布局），补丁 `optional: true`：没装实验性 Inspector 的 profile 报「不适用」而不是失败。`selfcheck` 新增「Inspector 状态帧不崩宿主」层。

## 验证

- `node --test test/patch-anchors.test.mjs`：锚点、两处改写、只碰目标调用点、幂等，以及「旧预算必然溢出 / 新预算装得下」的算术断言；
- 真实宿主副本应用 #92：`pending → applied → already`（二次应用字节不变），`node --check` 通过，模块可导入且 `resolveInspectorOptions().maxSourceFrameBytes === 1048576`；
- `npm test`：419 条，397 pass / 0 fail / 22 skip。

## 不变

权限、提示词、预设、更新偏好、用户配置均不改；不自动应用宿主补丁、不自动重启——升级后仍要手动「应用」+ 完整退出重开。

如果某个 profile 不想动宿主文件，也可以在 profile patch 层把 `experimental-inspector` 的 `config.maxSourceFrameBytes` 抬到 1 MiB（注意该层 `config` 是整段替换，`captureFetch` 要一起写），效果等价。
