# 1.7.16 — 修复全新安装被 Gitee 跳转域名拦住

这一版没有新功能。它修的是**所有新机器都装不上**的那个拦截：Gitee 把 release 附件重定向到 `foruda.gitee.com`，而安装链路上的三处域名白名单没有跟上，归档下载被判为不可信后直接中止。

## 症状

在另一台电脑上跑 `install.ps1`（或 `install.sh`）时，引导器能取到元数据、能确定版本，但到下载归档那一步失败：

```
Downloading Purge Community 1.7.15...
Release download failed: stage=archive host=gitee.com transport=fetch attempt=1/3
code=UNTRUSTED_RELEASE_URL. Nothing installed.
```

`code` 是 `UNTRUSTED_RELEASE_URL` 而不是超时、不是证书错误、不是 404——说明请求本身没问题，是**落点域名不在允许列表里**。

## 根因

Gitee 的 release 附件下载现在经过两次 302：

```
https://gitee.com/n-sky/dsh-purge/releases/download/v1.7.15/<file>
  → https://foruda.gitee.com/attach_file/<id>/<file>?token=…&ts=…&attname=…
```

`foruda.gitee.com` 是 Gitee 新的附件托管域名。引导器在跟随跳转后会用 `trustedURL()` 复核最终地址，白名单里只有 `gitee.com` / `file.gitee.com` / `objects.gitee.com`，于是判定不可信。这个检查本身是对的——它挡住的是「被重定向到任意主机」——只是域名清单过期了。

同样的清单还有两处，都会在真机上撞到：

| 位置 | 影响 |
| --- | --- |
| `scripts/bootstrap-install.mjs` 的 `hosts` | 独立安装器 / 引导安装，也就是全新安装的主路径 |
| `lib/update-http.js` 的 `UPDATE_HOSTS` | 面板「检查社区版更新 → 安装」，以及插件内所有走 update-http 的请求 |
| `lib/update-source.js` 的 `hosts` | 发行源探测（release 页 / 资产基址的信任范围） |

## 改法

三处白名单各加 `foruda.gitee.com`，并留注释说明它是什么、为什么不能删。除此之外**没有**放宽任何判定：

- 仍然只允许 `https:`，仍然拒绝带用户名/密码的 URL，仍然只认 443；
- 仍然逐跳复核，跳转落点不在白名单里就中止；
- 仍然强制 `SHA256SUMS.txt` 校验，失败即「Nothing installed」；
- 仍然不关闭证书校验、不改全局代理、不引入镜像旁路。

也就是说，修的是「清单过期」，不是「检查太严」。

## 验证

- 用真实引导器对真实发行源跑 `bootstrapInstall({dryRun:true})`：输出 `Downloading Purge Community 1.7.15...` → `SHA256 verified; dry run, nothing installed.`，返回 `{version:"1.7.15", dryRun:true}`。修之前同一调用在 `stage=archive` 抛 `UNTRUSTED_RELEASE_URL`。
- 另从 release 直接下载 tgz 与 `SHA256SUMS.txt`，`sha256sum -c` 通过，tgz 内 `package.json` 版本为 1.7.15。
- 三处白名单的改动只加域名，已有条目与判定顺序未动；`node --check` 通过。

## 升级

已经装好的机器不受影响（它们不走引导器）。新机器直接用 1.7.16 的引导器即可；装完是 1.7.15 还是 1.7.16，取决于发行源当时的 `releases/latest`——本版发布后就是 1.7.16。

装完仍需从系统托盘完整退出 DSH 再打开：插件运行时代码不会热加载，这一点 1.7.15 起面板会明确提示。
