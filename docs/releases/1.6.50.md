# 1.6.50 — 更新源可配置（GitHub / Gitee）

## 问题

面板「维护：更新与本机备份」显示：

```
无法读取社区发行列表：GitHub API 额度耗尽（HTTP 403），重置时间 …；
releases.atom 降级失败：未找到可验证的发行安装包
```

原因不在仓库、也不在认证：社区发行列表被写死成上游 GitHub 仓库
（`lib/community.js` 的 `REPOSITORY`），匿名请求只有 60 次/小时；用完之后
`api.github.com` 一律 403，而 `releases.atom` 兜底又要求发行里带
`SHA256SUMS.txt`，上游没有这样的发行，于是降级也失败。

对一个自托管、内网、或 GitHub 不可达的部署来说，这条链路等于永久失效。

## 改法

新增 `lib/update-source.js`，把「发布源」抽成 provider：

| provider | 发行列表 | 单标签元数据 | 标签兜底 | 发行页 / 资产 |
| --- | --- | --- | --- | --- |
| `github`（默认） | `api.github.com/repos/<repo>/releases` | `…/releases/tags/<ref>` | `releases.atom` | `github.com/<repo>/releases/…` |
| `gitee` | `gitee.com/api/v5/repos/<repo>/releases` | `…/releases/tags/<ref>` | `/tags`（无 atom） | `gitee.com/<repo>/releases/…` |

配置（两个环境变量，由启动 DSH 的进程继承）：

```sh
PURGE_UPDATE_REPO=n-sky/dsh-purge        # 或 https://gitee.com/n-sky/dsh-purge.git
PURGE_UPDATE_PROVIDER=gitee              # 可省略：URL 里带 gitee.com 时自动识别
```

不设这两个变量时，发布源仍是 `kingcharleslzy-ai/dsh-purge`（GitHub），
行为与 1.6.49 完全一致。

## 跟随源一起切换的东西

- `lib/community.js`：`releasedVersions()` 的列表 URL、`prepareRelease()` 的
  单标签元数据 URL、安装包身份校验（`package.json` 的 `repository.url` 现在
  同时接受本仓库声明值与当前源的 URL 集合）。
- `lib/update.js`：标签兜底条目的发行页 / 资产 / 校验清单 URL 由 provider 生成；
  状态文案里的平台名跟随实际源（不再固定写「GitHub API 不可用」）。
- `lib/update-net.js`：镜像源模式下，只存在于 GitHub 的「上游版本探测」
  （`remoteHeadSha` / `remotePackageVersion` / `listGithubTags`）直接返回空，
  不再向 GitHub 打无效请求；归档 URL 切成 Gitee 的 `repository/archive/<ref>`。
- `lib/update-http.js`：`UPDATE_HOSTS` 增加 `gitee.com`、`file.gitee.com`、
  `objects.gitee.com`（资产会 302 到文件域，跳转落点必须在白名单内）；
  `GITEE_TOKEN` 以 `Authorization: token …` 发送，`GITHUB_TOKEN` 仍为 `Bearer`，
  两者互不串用，跨域不转发。
- `lib/index.js`：面板/接口返回的 `repository` 是**当前生效**的仓库名。

## 行为约定

- 配置错就报错：`PURGE_UPDATE_PROVIDER` 不是 `github|gitee`，或
  `PURGE_UPDATE_REPO` 不是 `owner/repo`（含 URL / scp 形式）时抛错，
  不静默退回默认源——否则「以为切到了镜像，其实还在打 GitHub」最难排查。
- 校验强度不变：任何来源的 tgz 都要过 `SHA256SUMS.txt` / API digest 与包身份检查，
  镜像不等于放行。
- 降级仍要可解释：标签兜底必须逐条核对 `SHA256SUMS.txt` 才判定可安装，
  列表与降级原因照旧展示在面板上。

## 测试

新增 `test/update-source.test.mjs`（7 条，全部通过）：

1. 默认仍是上游 GitHub 源（列表 URL / provider / 标签文案）；
2. `owner/repo` 只换仓库、不换平台；
3. 仓库 URL 里的 `gitee.com` 推断出 provider；
4. Gitee 源的列表 / 元数据 / 标签 / 资产 / 校验清单 / git URL / 主机名单 / 文案全套；
5. 配置错误立即抛错（不会被静默忽略）；
6. 传输层接受 Gitee 主机，`GITEE_TOKEN` 走 `token`、`GITHUB_TOKEN` 走 `Bearer`、匿名不发认证头；
7. scp 形式（`git@gitee.com:owner/repo.git`）也能识别。

全量 `npm test`：363 条 → 370 条，新增 7 条全过；历史 22 条失败与本次改动无关。

## 升级须知

- 只是「读发行列表」的源变了，安装行为、补丁、权限、提示词都不动。
- 若你已把仓库镜像到 Gitee，还需要在 Gitee 上**发布一个 Release**，并附上
  `dsh-purge-community-<version>.tgz` 与 `SHA256SUMS.txt`；只有 tag 而没发行附件时，
  降级路径会因为没有校验清单而拒绝安装（这是故意的）。
- 切换源只影响本机环境变量；要长期生效，请把变量写进启动 DSH 的那个进程环境
  （例如桌面快捷方式、服务定义或 shell profile），不要在插件里改全局设置。
