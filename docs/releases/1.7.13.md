# 1.7.13 — 面板按诊断台重做

左侧栏那个整页面板是本插件的主界面，但它一直是「卡片套卡片 + 一句话里塞三个按钮」：补丁数一屏出现三次（状态条、hero、补丁明细），`卸载` 和 `应用` 一样响，`▶ ✓ 已从解包目录启动` 像调试输出，`破甲自检 1 层需确认 · 查看逐层 重测 探针` 把四个控件塞进一句话。本版按 unslop 的九道工序重排：功能、文案、接口一字未改，只改呈现。

## 方向

诊断台 / 补丁台账。它回答的是「82 条宿主补丁到底在不在位」，所以界面像一块仪表而不是一张宣传卡：中性灰做底、发丝线做分隔、数字全部等宽，绿色只出现在状态上（圆点、刻度、徽标），不刷在按钮上。全屏只有一个高光——`74 / 76` 大号数字下面那把 82 格刻度尺，每条补丁一格。

## 一屏之内改了什么

- **页头**：`StatusStrip` 从一句话拆成四格读数：宿主（圆点 + `0.2.2-rc.1`）、兼容（`已回归验证`）、补丁（`74/76`）、插件（`1.7.12`）。标签 12px 在上、值 12.5px 等宽在下，列间一条竖细线。
- **主区**：`.dshpp-hero` 变成 `minmax(0,1fr) 188px` 两栏。左栏是这个版本的主角——`74 / 76 条已生效`（40px 等宽、`tabular-nums`）+ 刻度尺 + 图例（已生效 / 待应用 / 不适用 / 共 82，零项自动隐藏）+ 一句 12.5px 的操作提示。右栏是动作：`应用`（36px 墨色实心）、`刷新`、分隔线下的 `还原` / `卸载`。
- **去重**：`74/76` 只在 hero 出现一次。折叠行的 meta 只报差异（`2 待应用` / `全部在位`），版本管理行报 `本机 v1.7.12 · 正式版`。
- **折叠统一**：`版本管理` / `补丁明细` / `高级选项` 以前是三种外观（卡片内的 details、裸 details、裸 details），现在都是 `details.dshpp-expand`：44px 行高、左侧箭头、右侧 muted meta。
- **解释文字**：「待应用=原文还在。跳过=当前版本不需要这条…」那 500 字拆成 `dl.dshpp-defs` 三条名词——待应用 / 跳过 / 钩子拦截，每条一句。
- **破甲与维护**：两节各有 `h3` 节标题。自检与强化段变成行（名字 + 状态 + 行尾动作 `重测` / `探针` / `关闭`），逐层自检收进折叠；备份区从「卡片里的卡片」变成 `h4` 子标题 + 一行按钮。
- **危险动作**：`还原` / `卸载` 默认是 26px 灰字，悬停才变红；实心红只保留在卸载确认弹窗里。`应用` 是整屏唯一的实心按钮，深色主题下反相成浅底深字。

## 顺手修的四件事

1. `提示词` / `规则` / `技能` / `更多` 四个页签用的 60 个 `.dshpp-*` 类在新 `page.css` 里没有规则（旧规则随重写一起没了），页面一度退化成浏览器默认控件。本版把这些类全部补回：`.dshpp-head`、`.dshpp-block*`、`.dshpp-split`、`.dshpp-rulelist/-ruleitem/-rule-ops`、`.dshpp-editor`、`.dshpp-cwd-*`、`.dshpp-create*`、`.dshpp-checks` 等。
2. `.dshpp-field` 有两种语义——settings-form 里是「标签 + 控件的网格包装器」，rules/skills 里是输入框自身的类。旧规则让输入框继承 168px 网格宽度和标签样式，现在拆成 `div.dshpp-field` 与 `input.dshpp-field`。
3. `rules.js` 的输入框没有 `type` 属性，`input[type="text"]` 选不到它们（边框不可见）。改成 `input:not([type="checkbox"]):not([type="radio"])`。
4. `逐层自检` 在夹具缺 `applied` / `required` 字段时打印 `undefined/undefined`，现在缺字段显示 `—`。

## 不改的东西

- 没有任何宿主补丁或锚点变动：**升级后不需要重新「应用」补丁**，也不需要处理换包。
- 接口、文案、locale key、按钮行为、备份与回滚流程全部照旧。
- 面板版本仍来自后端运行时事实（1.7.10 的机制），`client.js` 头部标记随 `package.json` 一起变成 1.7.13。
