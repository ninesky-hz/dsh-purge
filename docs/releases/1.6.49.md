# 1.6.49 — 启动自愈：补 git 转发器

## 症状

在 DSH Desktop `0.2.1-rc.2` 的「添加插件」里安装 git 依赖（实测 `https://gitee.com/n-sky/dsh-purge.git`）会直接失败：

```text
[ERR_PNPM_GIT_RESOLVE_FAILED] Failed to resolve git dependency "https://gitee.com/n-sky/dsh-purge.git":
git ls-remote failed: 'git' 不是内部或外部命令，也不是可运行的程序或批处理文件。
```

同一个 URL 在普通终端里用系统 pnpm 或 DSH 自带 pnpm 都能装（`Done in 21.9s`），所以不是仓库、不是 Gitee、也不是认证问题。

## 根因

桌面主进程 `lib/main.js` 构造 pnpm 子进程环境时：

```js
PATH: `${bin}${delimiter}${environment.PATH ?? ""}`
```

Windows 上 `process.env` 的键保留原始大小写（常见为 `Path`），取不到大写 `PATH` 就退化成空串，于是子进程 PATH 被截成**只有** `resources/runtime/bin` 一个目录。该目录里只有 `node` 与 `node.cmd`，没有 git，`pnpm` 调 `git ls-remote` 便报「不是内部或外部命令」。

复现方式：把 PATH 收窄成只有 `D:\DeepSeek Harness\resources\runtime\bin`，用插件自带 pnpm 安装同一 URL，报错与界面逐字一致；不覆盖 PATH 时同一命令成功。

## 修法

插件启动（`applyHostHooks`）时调用 `ensureRuntimeGitShim()`：

- 在 `<resources>/runtime/bin/git.cmd` 写入 50 字节转发器：

  ```bat
  rem dsh-purge-git-shim — auto-installed by dsh-purge; safe to delete
  @echo off
  "C:\Program Files\Git\cmd\git.exe" %*
  ```

- 内容以 `dsh-purge-git-shim` 标记识别，幂等：已是本插件写的就跳过。
- 该路径若已有**别人**写的 `git.cmd`，不覆盖，报 `file_conflict` 并保留原文件。
- 若已有的是**纯转发到同一个 `git.exe`** 的 `git.cmd`（例如按维护文档手工补的），就地接管并补上标记，不报冲突。
- 找不到系统 git（`PATH`、`ProgramFiles`、`LOCALAPPDATA\Programs\Git` 都探不到）时 fail-closed，不写半成品。
- 只认 `git.exe`，避免把自己写的 `git.cmd` 当成系统 git 而递归。
- 写入走「临时文件 + rename」，被占用时下次启动重试。

`purge_status` 增加 `git shim / runtime` 一行（`✓` 已就绪 / `✗` 缺失或被占用 / `·` 非 Windows 或非桌面宿主），面板不必进终端就能看出状态。

## 实测（Windows 11 · DSH Desktop 0.2.1-rc.2 · pnpm 11.28.5）

| 场景 | 结果 |
| --- | --- |
| PATH 正常，装 `https://gitee.com/n-sky/dsh-purge.git` | `+ dsh-purge-community …` / `Done in 21.9s` |
| PATH 只剩 `runtime/bin`（无 git.cmd） | 复现界面报错，`EXIT=1` |
| PATH 只剩 `runtime/bin`（有本插件写的 git.cmd） | `Done in 9.6s`，日志可见 `git config --get core.sshCommand` 与 `git ls-remote -- <url> HEAD` 两次调用 |

## 升级与回滚

- 厂商升级 DSH 会重建 `resources/runtime`，转发器随之消失；下次启动插件会重新补上，无需人工干预。
- 回滚：删除 `<resources>/runtime/bin/git.cmd` 即可，无其它副作用。
- 这条修复只影响「桌面主进程派生的 pnpm 子进程」，不改宿主 `main.js`，也不动全局 npm/pnpm 配置。

## 测试

新增 `test/runtime-compat.test.mjs`（6 条，`node --test` 全过）：

1. 写入转发器、CRLF 行尾、重复调用幂等；
2. 外来 `git.cmd` 原样保留并报 `file_conflict`；
3. 纯转发器就地接管（`adopted`）并补标记；
4. 探不到系统 git 时不落任何文件；
5. 非 Windows 或没有 `runtime` 目录时跳过；
6. `resolveSystemGit` 优先显式路径，且绝不选中 `git.cmd`。
