## 改了什么

### #62 `OFFICIAL_TOOL_ASK_FAILOPEN`

rc.5 的 `dsh-tools/lib/index.js`（运行时入口 bundle）把字面量 `undefined` 改成 `void 0`、`switch` 多一层缩进，并新增了 `exec.agent === void 0` 的 deny 分支。旧锚点只在 `lib/types/index.js`（编译残留）命中，入口 bundle 实际没被改。

新增三条 bundle 变体：

- `approval === void 0` → allow（无审批服务）；
- `exec.agent === void 0` → allow（没有 agent 可路由，等于没有审批通道）；
- 更深缩进的 `case "unavailable"` → allow。

`rejected` / `cancelled` 仍然 deny，语义与旧版一致：只放行「没有通道」，不替代用户拒绝。

### #26 `MINIMAL_PERSONA_PURGE`

rc.5 的 `dsh-web-app/presets/minimal.patch.yml` 在 persona 之后、persistent-shell 之前插入了 `tool-fs` 行，旧锚点要求紧跟 `persistent-shell`，于是只落下了 `complete: false`，`agent-instructions` 没插进去（minimal 预设不会加载 workspace `AGENTS.md`）。

新增两条变体，把 `agent-instructions` 插到 `tool-fs` 之前；`prefix: ""` 仍由 #43 完成。

### #57 `DEEPSEEK_SYSTEM_ROLE`（optional）

rc.5 的 responses 通路（`pi-ai/dist/api/openai-responses-shared.js`）变量名回到 `instructionRole`，判定仍是 `compat?.supportsDeveloperRole !== false`。旧补丁只匹配 `const role = ...`，responses 路径没有白名单围栏。

新增一条变体，responses 路径也只对 `api.openai.com` / `azure.com` 保留 developer role，其余回退 system。

## 边界与注意

- rc.5 不再随包发 `dsh-client-runtime` / `dsh-client-ui-slots`；`slots` 服务改由 `dsh-client-ui-renderer` 提供，`sessions` 由 `dsh-api-session-controller` 提供。面板用到的 `slots` / `locale` / `sessions` / `conversation` / `uiWorkspace` 服务与 4 个 slot 名在 rc.5 均存在；`package.json` 的 `dsh.client.inject` 为兼容老宿主的旧名保留，client-modules 对不存在的依赖行会跳过。
- rc.5 的 `@deepseek-ai` 包里找不到 `desktopRuntime` / `desktopActions` 服务，优雅重启会回退到 helper 路径；1.7.4 起桌面解包后本来只写盘不自动重启，影响低。
- 磁盘上应用补丁不等于当前进程已加载；仍要完整退出重开，再跑 `selfcheck` 确认。
